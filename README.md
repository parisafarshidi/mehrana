# مهرانا

پلتفرم فارسی همراه خانواده در مسیر رشد و تغذیه کودک. این مخزن نسخه بازسازی‌شده رابط عمومی و پایه سئوی فنی را در کنار اپلیکیشن فعلی خانواده نگه می‌دارد.

## اجرای محلی

Node.js نسخه ۲۲.۱۳ یا جدیدتر لازم است (از `node:sqlite` استفاده می‌شود).

```bash
npm install
npm run dev
```

رابط Vite روی `http://localhost:5173` و API روی `http://127.0.0.1:8787` اجرا می‌شود. در محیط توسعه، کد OTP در ترمینال سرور نمایش داده می‌شود؛ این روش صرفاً برای توسعه است.

## ساخت نسخه انتشار و SEO

```bash
# دامنه واقعی را قبل از build تنظیم کنید
$env:SITE_URL="https://your-real-domain.example"  # PowerShell
npm run build
```

فرایند build ابتدا Vite را اجرا می‌کند و سپس `scripts/prerender.js` صفحات عمومی را به HTML قابل خزش تبدیل می‌کند. خروجی شامل این موارد است:

- HTML پیش‌رندرشده برای صفحه اصلی، درباره مهرانا، امکانات، برنامه روزانه غذایی، مجله و مقاله‌های نمونه، اشتراک و حریم خصوصی
- عنوان، توضیح متا، canonical و Open Graph مستقل برای هر صفحه
- داده ساختاریافته JSON-LD برای صفحات
- `sitemap.xml` و `robots.txt`

دامنه پیش‌فرض `https://mehrana.example` صرفاً placeholder است و نباید در محیط واقعی استفاده شود. پیش از انتشار `SITE_URL` را روی دامنه نهایی تنظیم کنید. صفحات حساب مادر، داشبورد و مسیرهای خصوصی باید پشت احراز هویت بمانند و در موتور جست‌وجو ایندکس نشوند. `robots.txt` جایگزین کنترل دسترسی نیست.

## ساختار فعلی

- `src/App.jsx`: اپلیکیشن فعلی خانواده و مسیرهای داخلی
- `src/PublicPage.jsx` و `src/public-page.css`: صفحات عمومی و محتوای قابل خزش
- `src/publicContent.js`: منبع مشترک اطلاعات متا، صفحات و مقاله‌های عمومی
- `scripts/prerender.js`: تولید HTML ایستا، sitemap و robots
- `server/index.js`: API فعلی Node.js و SQLite
- `server/data/`: محل پایگاه داده محلی (در ZIP اولیه فایل پایگاه داده وجود نداشت)

## برنامه روزانه غذایی شخصی‌سازی‌شده

مسیر `/planner` اکنون با نام «برنامه روزانه غذایی» معرفی می‌شود و به‌صورت شفاف نشان می‌دهد که قابلیت هنوز فعال نیست. تا قبل از آماده‌شدن پایگاه دانش غذایی، منطق قواعد ایمنی، احراز استحقاق اشتراک، ذخیره سابقه و بازبینی علمی، نباید برنامه‌ای به‌عنوان توصیه اختصاصی تولید شود.

الزامات نهایی این قابلیت:

- شخصی‌سازی با سن دقیق، آمادگی رشدی، مهارت نشستن/بلع/خوردن، سابقه غذاهای معرفی‌شده و پذیرفته‌شده، حساسیت و واکنش، الگوی شیر و محدودیت‌های سلامت
- نمایش غذا و ترکیبات، بافت، مقدار راهنمایی‌شده و انعطاف‌پذیر، زمان‌بندی منعطف، روش آماده‌سازی و هشدارهای ایمنی
- تفکیک برنامه پیشنهادی از مقدار واقعی مصرف‌شده
- توقف یا علامت‌گذاری برنامه در واکنش مشکوک یا مشکل بلع؛ بدون تجویز خودکار غذای جایگزین یا رژیم درمانی
- کنترل دسترسی پولی در سمت سرور، نه فقط مخفی‌کردن دکمه در رابط کاربری

## معماری هدف پیش از عرضه عمومی

نسخه موجود هنوز محصول آماده عرضه عمومی نیست. موارد زیر باید در مراحل بعدی، با migration نسخه‌دار و بدون حذف داده‌های قبلی، تکمیل شوند:

1. جداسازی احراز هویت مادر و مدیر؛ ایجاد اولین مدیر فقط از مسیر راه‌اندازی امن؛ ورود مدیر با رمز عبور قوی و OTP.
2. کنترل دسترسی در تمام APIها، اعتبارسنجی سمت سرور، محدودیت نرخ پایدار برای OTP و درخواست‌ها، کنترل Origin/CSRF و مدیریت نشست.
3. ثبت audit log برای ورود مدیر و مشاهده/ویرایش/حذف/خروجی‌گرفتن از اطلاعات حساس؛ بدون ثبت رمز، OTP، توکن یا جزئیات کامل پزشکی در log.
4. جداول مستقل برای کودک، پروفایل تغذیه، غذاها، دستورها، سابقه معرفی غذا، واکنش‌ها، برنامه روزانه نسخه‌دار، وعده‌ها، ثبت مصرف و استحقاق اشتراک.
5. پنل مدیریت محتوا با وضعیت پیش‌نویس/انتشار، نسخه‌بندی، slug، عنوان و توضیح SEO، نویسنده و منابع علمی؛ ویرایشگر بصری در مرحله CMS.
6. سیاست شفاف رضایت، نگهداری، اصلاح، دریافت نسخه و حذف داده؛ پشتیبان‌گیری و آزمون بازیابی SQLite و فایل‌های رسانه‌ای.
7. استقرار HTTPS، reverse proxy امن، محدودیت درخواست، مدیریت اسرار در environment، مانیتورینگ و آزمون امنیتی مستقل.

## محدودیت‌های فعلی

- ZIP اولیه شامل فایل واقعی SQLite نبود؛ بنابراین هیچ داده واقعی خانواده‌ای بررسی یا تغییر داده نشده است.
- پرداخت، اشتراک واقعی، پنل مدیر، CMS کامل و موتور تولید برنامه غذایی هنوز پیاده‌سازی نشده‌اند.
- اتصال پیامک در تولید نیازمند سرویس‌دهنده و تنظیمات معتبر است.
- پیش‌رندر برای صفحات عمومی پیاده شده؛ مسیرهای خصوصی همچنان نباید از نظر امنیتی به `robots.txt` متکی باشند.

## پایگاه داده

پایگاه داده پیش‌فرض در `server/data/mehrana.sqlite` ساخته می‌شود. برای مسیر دیگر، `MEHRANA_DB_PATH` را تنظیم کنید. از آنجا که داده‌های واقعی در ZIP موجود نبودند، پیش از اجرای نسخه روی محیط دارای داده، پشتیبان بگیرید و migrationها را روی کپی آزمایش کنید.

## بانک کلمات کلیدی و نقشه محتوایی

فایل `src/seoKeywordBank.js` بانک اولیه عبارت‌های جست‌وجوی مهراناست. عبارت‌ها در خوشه‌های موضوعی دسته‌بندی شده‌اند و هر خوشه یک صفحه هدف دارد تا چند صفحه مهرانا برای یک نیت جست‌وجوی یکسان با هم رقابت نکنند.

- `status: published` یعنی صفحه هدف در `src/publicContent.js` وجود دارد.
- `status: planned` یعنی خوشه تعریف شده اما صفحه محتوایی آن هنوز ساخته و بازبینی علمی نشده است.
- حجم جست‌وجو و سختی کلمه عمداً حدس زده نشده‌اند؛ باید بعداً با داده Search Console و ابزار تحقیق کلمات کلیدی تکمیل شوند.

بررسی ساختار بانک:

```bash
npm run seo:check
```

این بانک برای برنامه‌ریزی محتواست؛ قرار نیست همه عبارت‌ها به‌صورت تکراری داخل متن مقاله چپانده شوند. هر صفحه باید یک نیت اصلی را پاسخ دهد و عبارت‌های نزدیک و هم‌معنی را طبیعی پوشش دهد.

## مدیریت مقالات (CMS)

پس از دریافت این نسخه، یک‌بار مهاجرت دیتابیس را اجرا کن:

```bash
npm run db:migrate
```

سپس سرور API و فرانت‌اند را طبق روال توسعه اجرا کن و وارد مسیر `/admin/login` شو. پس از ورود دومرحله‌ای، در داشبورد مدیریت می‌توانی مقاله جدید بسازی، پیش‌نویس ذخیره کنی، مقاله را منتشر یا ویرایش و حذف کنی.

### فیلدهای مقاله

- عنوان و آدرس یکتای انگلیسی (slug)
- خلاصه و متن مقاله
- دسته‌بندی
- عنوان و توضیحات متا
- کلمات کلیدی مرتبط
- نام نویسنده و بازبین علمی
- منابع/یادداشت‌های بازبینی
- وضعیت پیش‌نویس یا منتشرشده

### API محتوا

- `GET /api/articles` فهرست مقالات منتشرشده
- `GET /api/articles/:slug` دریافت یک مقاله منتشرشده
- `GET /api/admin/articles` فهرست مقالات برای مدیر (نیازمند نشست مدیر)
- `POST /api/admin/articles` ایجاد مقاله (نیازمند نشست مدیر)
- `PUT /api/admin/articles/:id` ویرایش مقاله (نیازمند نشست مدیر)
- `DELETE /api/admin/articles/:id` حذف مقاله (نیازمند نشست مدیر)

متن مقاله در نسخه اول به‌صورت متن ساده با پاراگراف‌بندی ذخیره می‌شود؛ ویرایشگر غنی، بارگذاری تصویر، پیش‌نمایش، گردش‌کار تأیید علمی و به‌روزرسانی خودکار sitemap برای مقالات جدید در مرحله بعدی توسعه قرار دارند. صفحات CMS از مسیر API فقط پس از انتشار عمومی می‌شوند. اطلاعات سلامت واقعی را در محیط نمایشی وارد نکن.

## Feature bundle: food, breastfeeding, sleep, reminders, activities, health records and family plans

Run database migrations after updating the source:

```bash
npm run db:migrate
```

The administrator can manage the additional content library at `/admin/modules` after signing in. It includes food detail pages, breastfeeding topics, milestone editorial content, daily activity ideas, sleep guides and reminder templates. Public food and breastfeeding entries are served from `/api/content` and are available at `/food-guides/:slug` and `/breastfeeding-guides/:slug`.

The family workspace includes first-pass sleep logging, reminders, activity completion, child health record entries and a printable monthly summary. These are family record-keeping tools and do not interpret medical results or diagnose conditions. Data is stored with the authenticated account document in SQLite.

Migrations `004_feature_content.sql` and `005_family_subscriptions.sql` add the editorial library and subscription/family-sharing database foundation. Real payment processing, invitation delivery, secure shared access, role enforcement and server-side subscription entitlements are not switched on in this phase; the UI labels these limits explicitly. Before public deployment, complete authorization, privacy review, backups, and integration with the selected SMS/payment providers.
